## 四、问题与解决

| 问题 | 原因 | 措施 / 遗留 |
|---|---|---|
| 驳回后“重新生成”实际只重跑校验 | 重试时沿用旧 `draft`，Workflow 的 `intent` 判断为已有草稿，跳过检索与生成 | 重试清空 `draft`，把上一版草稿与驳回意见写入 `task`；E2E 确认节点含 `retrieval`、`draft_llm`；后端测试 104/104 |
| 引用摘录看不到支撑事实 | `CitationCollector` 固定截取段首 200 字符 | 上限改为 500 码点并补测试；最终评测摘录支持事实 10/10；这是已执行的优化 |
| Workflow 视图拿不到引用 | 检索节点输出存在 `[...]` 与 `{"value":[...]}` 两种形状，字段有嵌套/顶层差异 | 新增 `WorkflowEventCollector` 兼容两种形状，复用 `CitationCollector` 去重排序；单测 3/3、E2E 17/17 |
| A/B 引用中存在低相关文档 | Dify TopK=4，低分文档约 0.43–0.51 仍被返回 | 记录 BC-02；下一步只改相似度阈值或 TopK 一个变量并复测，避免同时改动 |
| Windows 终端中文/换行导致文档与脚本噪声 | Git Bash 编码与 CRLF/LF 混用 | 统一 UTF-8 运行评测；按索引 EOL 归一化文本；不把终端编码问题误判为服务端缺陷 |

## 六、学习笔记（1 个概念 + 1 个踩坑 + 1 个待验证问题）

- **概念：Human-in-the-loop Workflow 状态机。** `human_input` 让 Workflow 在上游完成后暂停并返回表单；后端用 `runId` 对外、`form_token` 对内保存暂停凭据，确认后提交表单恢复执行。状态必须显式区分 `WAITING_CONFIRM`、`RETRYING`、`SUCCEEDED`、`FAILED`、`REJECTED`，并禁止非 `SUCCEEDED` 导出。
- **踩坑：重试传旧草稿会“假重生成”。** 非空 `draft` 让 Workflow 走已有草稿分支，只重跑校验；解决是重试时清空 `draft`，并把旧草稿和驳回意见附加到任务描述，强制重新检索与生成。
- **待验证问题：检索阈值与召回率的平衡。** 低相关引用（BC-02）可通过提高相似度阈值或降低 TopK 过滤，但可能伤害本已命中的题目；下一步固定评测集，只改一个变量，复测命中率、拒答率与引用精度。
