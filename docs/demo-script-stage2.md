## 14. 设计讲解（7 分钟）提纲

1. **学了什么**：RAG 的切分/Embedding/检索/引用链；Workflow 的工具、分支、人工确认与兜底；评测口径与 badcase 归因。
2. **怎么设计**：Vue3 → Spring Boot → Dify；A/B 双库只改切分变量；引用由后端统一映射并先于 `done` 下发；Workflow 暂停状态由后端保管，导出强制 `SUCCEEDED`。
3. **为什么这样选**：Dify 负责 RAG/Workflow 编排与私有化接入；Spring Boot 负责鉴权、白名单、错误码、状态机和统一引用，避免前端持有 Dify Key；内存状态是可演示的最小实现，生产化需持久化。
4. **工程细节**：上传演示用临时库隔离，避免现场写操作污染 B 库评测数据；15 题评测使用固定题集，单题抽样只用于展示。
5. **失败案例与改进**：BC-01 摘录截断 → 200/500 字符上限 → 复测 10/10；BC-02/03 作为未完成优化如实说明下一步实验设计。
